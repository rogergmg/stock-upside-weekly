# Historical evaluation

Use a frozen observation for each company and reference close. Store the predictor inputs separately from subsequent outcomes. One observation comprises a historical snapshot in the [calculator format](analysts.md) and the later split-consistent price-only value for one original share.

Run `python3 scripts/evaluate.py cases.json` from the skill directory. The file is a JSON array. Each item has a `snapshot` object and an `outcome` object with `date`, `value_per_original_share` and `source`. Set `outcome` to null for an unresolved or unmatured observation. Use the same issuer and listing across both dates. Split adjustments must preserve the economic value of one original share. For delistings reconcile the cash/share consideration or evidenced zero recovery at the evaluation date. Missing outcomes are disclosed separately.

1. Choose an investable historical universe and calendar before looking at outcomes. For each reference close verify that the issuer cleared US$20 billion at that time. Include companies that later exited the index. Determine the membership, cap, share count, FX, calls, withdrawals, corporate actions and filing versions using information public by that close. Resolve whether same-day releases occurred before or after the cutoff. Today's analyst roster creates survivorship bias.
2. Run the identical group of dated 12-month targets through equal weighting and 45-, 90- and 180-day half-lives. Compare their implied price returns from the reference close against the realized 12-month price return. This tests the user's ranking signal even though older calls have shorter remaining lives. Test individual analysts' original forecasting accuracy on the anniversary of their own issue dates in a separate analysis.
3. Use the first regular close on or after the anniversary, accounting for the exchange calendar. The helper accepts a seven-calendar-day tolerance to catch mistaken dates. Verify the actual first tradable session yourself. For a longer suspension reconcile the corporate action and outcome separately. Do not substitute a dividend-adjusted close. Never replace a missing value with zero.
4. Report paired observations, distinct companies, date range, coverage gaps, mean and median absolute error in percentage points and mean signed error. Below-zero signed error means the target understated the realized return. For discovery rankings, also compare within-date rank correlation on dates with a sufficient cross-section. Disclose thin or concentrated samples. Present non-overlapping sensitivity checks for repeated monthly snapshots of the same issuer.
5. If selecting a half-life, use earlier data for model selection and a later, untouched test period. Purge training observations whose outcome horizon overlaps the test start. Check results across sectors, market periods and held-out issuers. Report error differences against equal weighting on the same rows. Use paired resampling by issuer and time block for uncertainty when sample size supports it. A small replay verifies arithmetic only.

## Two archived observations used to check the calculator

A development check used the regular closes on April 25, 2024 for Microsoft and April 11, 2024 for JPMorgan Chase. Both cleared the size cutoff using share counts in filings already public at those closes. Benzinga's pre-earnings articles each selected five analysts. Of those calls the replay used three documented 12-month targets for Microsoft (BMO, UBS, Jefferies) and one for JPMorgan (BMO). Other targets lacked a matching horizon in the evidence used. BMO's disclosed default was 12 months. The narrow selection makes these inputs suitable for checking the calculation.
